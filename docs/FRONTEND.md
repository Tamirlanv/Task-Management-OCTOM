# Интерфейс OCTOM

## Запуск

Всё приложение (API, PostgreSQL, Redis, миграции, web):

```powershell
docker compose up -d --build --wait
```

Интерфейс: <http://127.0.0.1:3000>. Swagger: <http://127.0.0.1:8000/docs>.
В Windows без Docker CLI в PATH:

```powershell
& "$env:LOCALAPPDATA/Programs/DockerDesktop/resources/bin/docker.exe" compose up -d --build --wait
```

Разработка с hot reload (API должен быть запущен):

```powershell
cd frontend
npm.cmd ci
npm.cmd run dev
```

Vite: <http://127.0.0.1:5173>. Запросы `/api` проксируются на `127.0.0.1:8000`.
`API_PROXY_TARGET` позволяет выбрать отдельный тестовый API. Значение используется
только сервером Vite и не попадает в браузерную сборку.

## Пользовательские сценарии

- Регистрация и вход, выход, автоматическое обновление access-токена.
- Выбор и создание пространства; администратор может изменить или удалить его.
- Сводка текущих статусов, количества проектов, просрочек и ближайших сроков.
- График создания задач за 7/14 дней UTC. Это не история завершения: в модели нет
  событий завершения. Удалённые задачи в статистике не учитываются.
- Создание, редактирование и удаление проектов менеджером/администратором.
- Задачи: описание, статус, приоритет, локальный срок, исполнитель, до 20 тегов.
- Поиск с задержкой 350 мс, фильтры по проекту, статусу, приоритету, исполнителю,
  тегу и просрочке; сортировка и серверная пагинация.
- Управление участниками по email уже зарегистрированных пользователей и их ролями.
- Профиль и каталог тегов. Удаление требует отдельного подтверждения в интерфейсе.
- Адаптивный layout, клавиатурная навигация, native dialog с удержанием фокуса,
  сообщения об ошибках, загрузке и пустых результатах.

На главном экране нет подставных метрик. Иллюстрация карточки на странице входа —
декоративный пример. В локальной БД для проверки создано отдельное пространство
`OCTOM · Demo`; данные пользователей автоматически не добавляются.

## Архитектура

React + TypeScript (strict) + Vite; серверное состояние — TanStack Query.
Иконки — Lucide, график — SVG, стили разделены по зонам интерфейса.

```text
frontend/src/
  api/             HTTP, типы DTO, запросы, обновление токенов
  auth/            вход и регистрация
  components/      modal, pagination, feedback, selectors, sidebar
  features/
    dashboard/     статистика и график
    tasks/         фильтры, список и форма задачи
    catalog/       проекты, команда, настройки и теги
  lib/             форматирование и UI-политики
  styles/          базовые, адаптивные и компонентные стили
```

API сводки: `GET /api/v1/workspaces/{id}/overview`, доступен только участникам;
возвращает роль текущего пользователя и агрегаты по workspace. Подсчёт выполняется
в PostgreSQL, браузер не загружает все задачи для статистики. Серия содержит ровно
14 календарных дней UTC с нулями для пропусков. Текущие показатели отражают состояние
на момент запросов; одновременные изменения могут быть видны после обновления.

Запросы используют AbortSignal и таймаут 15 секунд. После мутаций кэш обновляется.
Справочники загружаются страницами по 50 записей с кнопкой «ещё»; нет скрытого
обрезания на первой сотне. Ошибки не вызывают бесконечных повторов.

## Сессии и границы MVP

Access/refresh-токены хранятся **только в памяти страницы**, не в localStorage,
sessionStorage или URL. После перезагрузки страницы нужен новый вход; это явно
указано на форме. Для постоянного входа следующим этапом нужен продуманный
HttpOnly/Secure cookie flow с CSRF-защитой. Текущий API поддерживает Bearer/JSON.

Параллельные 401 объединяются в одну refresh-ротацию. Потерянный ответ ротации
не повторяется: требуется вход, чтобы не вызвать replay-отзыв семьи токенов.
При смене аккаунта кэш очищается; запоздалые ответы предыдущей сессии отбрасываются.
Выход отзывает refresh-семью; выданные access-токены действуют до истечения срока.

UI скрывает недоступные действия, но права и tenant-изоляция обеспечиваются API.
Текст выводится React как текст; пользовательский HTML не исполняется. Nginx отдаёт
CSP, запрещает embedding и проксирует API на том же origin. Секретов в сборке нет.

Compose остаётся локальным окружением. Перед публичным запуском нужны TLS,
домен, постоянная безопасная сессия, доверенная цепочка reverse proxy для клиентских
IP/rate limit и проверки в целевых браузерах. API сейчас не доверяет forwarded
заголовкам: запросы через web-контейнер имеют один адрес прокси для IP-лимитов.

## Проверки

```powershell
cd frontend
npm.cmd run format:check
npm.cmd run lint
npm.cmd test
npm.cmd run build
```

Vitest проверяет конкурентный refresh, ошибки сессии/rate limit, запоздалые ответы,
UI-права и формат сохранения nullable-полей задачи. Полная проверка Python:
`./scripts/check.ps1` из корня. GitHub Actions содержит отдельную frontend job;
удалённый запуск CI ещё не выполнялся.

Browser smoke проверяется на локальной Docker-сборке: регистрация, вход, создание
пространства/проекта/задачи, изменение статуса, теги и поиск, защита последнего Admin,
адаптивная главная страница. Подробные результаты — в `VERIFICATION.md`.

Документация инструментов: [Vite](https://vite.dev/guide/),
[TanStack Query](https://tanstack.com/query/latest/docs/framework/react).
